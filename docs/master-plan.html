Scope reminder. All targets are Jayami's own locally hosted forks (Cal.com, Documenso, Medusa, Twenty) in Docker. Security content stays at QA test-design level (expected status codes, headers, scanner config). No exploit payloads. Ideation metrics are targets to measure, not claims.

1. Goal & what this showcases

Show that Jayami tests below the UI: HTTP contracts against the products' own OpenAPI specs, auth tokens minted per run, webhooks simulated with real signatures (HMAC / Stripe), and asynchronous chains (API → webhook/queue/worker → database) asserted at the database, not just the response code. The ideation brief asks for Playwright API + Docker Postgres, OpenAPI/AJV contracts, dynamic bearer tokens, HMAC/Stripe webhook simulation, async-chain assertions, atomic setup/teardown, contracts/ webhooks/ integration/ folders, and CI on Docker. The upstream gaps chosen here are where the inventory found None/Shallow depth: Documenso job runner, webhook trigger matrix, signature validity and Stripe; Cal inbound webhooks and tasker retries; Medusa webhook ordering and event-bus retries; Twenty receiver-side HMAC and delivery semantics.

  • Contract testing from the source of truth: Cal docs/api-reference/v2/openapi.json, Documenso GET /api/v2/openapi.json, Medusa www/apps/api-reference/specs/store/openapi.full.yaml, Twenty GET /rest/open-api/core. Validated with AJV, so schema drift fails the build.
  • Webhook engineering: a local receiver that verifies signatures over the raw bytes, records deliveries and can answer 500/timeout on demand. Outbound senders are simulated with real HMAC/Stripe signing.
  • Data integrity: every state-changing test asserts the DB row(s) through a read-only pg client (exact counts, no orphans) and cleans up in an atomic fixture.
  • Async discipline: expect.poll with explicit deadlines for queues and workers. No sleeps; the measured settle time is reported.

4. Environment setup per product

Cal.com

  • DB: Postgres localhost:5450 / calendso (packages/prisma/docker-compose.yml); migrate + seed as in P1.
  • APIs: web http://localhost:3000 (yarn dev), API v2 http://localhost:5555 (yarn workspace @calcom/api-v2 dev). Headers: cal-api-version: 2024-08-13 for bookings, 2024-09-04 for /v2/slots (from the controllers).
  • Dynamic token: API v2 key (Authorization: Bearer cal_…) created per run in global-setup via Settings → Developer → API keys. A scripted creation path is to verify; tables involved: ApiKey.
  • Webhook env: DAILY_WEBHOOK_SECRET set, and unset NEXT_PUBLIC_IS_E2E/INTEGRATION_TEST_MODE (otherwise the HMAC check is skipped: apps/web/app/api/recorded-daily-video/route.ts). Cron routes need CRON_API_KEY.
  • Oracles: tables Booking, Task, WebhookScheduledTriggers, BookingAudit; Mailhog API :8025/api/v2/messages.

Documenso

  • Run: npm run dx then npm run dev (:3000). Postgres 54320, Inbucket 9000, Gotenberg 3005.
  • Dynamic token: create an API token per run (Settings → API tokens; tRPC api-token-router), sent as the Authorization header on /api/v2/*. Model ApiToken.
  • Env: NEXT_PRIVATE_JOBS_PROVIDER="local" (default in .env.example), local signing cert apps/remix/example/cert.p12 via NEXT_PRIVATE_SIGNING_LOCAL_FILE_PATH, NEXT_PRIVATE_STRIPE_WEBHOOK_SECRET for the Stripe route apps/remix/app/routes/api+/stripe.webhook.ts.
  • Oracles: Webhook, WebhookCall (delivery log), BackgroundJob/BackgroundJobTask, DocumentAuditLog; Inbucket API.
  • Prior evidence: scripts/validation/documenso-probe-results.json (DOC-UP-4, recorded 2026-10-01 22:48 Colombo): zero-byte, EXE-as-PDF and corrupt PDF uploads to /api/files/upload-pdf returned 500; oversize returned 400.

Medusa

  • Harness used so far: monorepo integration-tests/http with scripts/portfolio-validation/docker-compose.yml (Postgres localhost:5433 medusa/medusa/medusa_validation, Redis 6380, MinIO 9001/9002). Stripe matrix fixture integration-tests/http/__fixtures__/anchor-c/medusa-config.js (ANCHOR_C_STRIPE_MATRIX=1, secret whsec_anchor_c_local_matrix_test_secret).
  • For P2 (black-box): pinned 2.21.2 app (to verify), with @medusajs/payment-stripe configured with the same test webhook secret, Redis event bus + locking module.
  • Dynamic tokens: admin POST /auth/user/emailpass → JWT; customer POST /auth/customer/emailpass/register → POST /store/customers → POST /auth/customer/emailpass; store calls carry x-publishable-api-key (PUBLISHABLE_KEY_HEADER in packages/core/utils/src/api-key/api-key-type.ts).
  • Webhook route: POST /hooks/payment/{provider} (provider id e.g. stripe_stripe). It emits PaymentWebhookEvents.WebhookReceived with delay: webhook_delay || 5000, attempts: webhook_retries || 3 and returns 200 (packages/medusa/src/api/hooks/payment/[provider]/route.ts). Signature verification happens later, in the subscriber.

Twenty

  • Run: twentycrm/twenty:2.44.0 + docker-compose.validation.yml (Mailpit, multi-workspace on, email verification off).
  • Dynamic tokens: GraphQL signIn → getAuthTokensFromLoginToken, or an API key per run (REST Authorization: Bearer). Seed roles: jane=Admin, jony=Member, phil=Guest (Apple).
  • Webhooks: outbound requests carry X-Twenty-Webhook-Signature, -Timestamp and -Nonce. Delivery to an internal host needs OUTBOUND_HTTP_ALLOWED_INTERNAL_HOSTS (admin DB config variable). Jayami's receiver: 127.0.0.1:4317 via host.docker.internal.
  • Prior evidence: TW-WH-1C: hmac_valid_first=true, nonce present, request_count=5 when the receiver returned 500 (scripts/validation/anchor-b-* results). OAS at /rest/open-api/core.
