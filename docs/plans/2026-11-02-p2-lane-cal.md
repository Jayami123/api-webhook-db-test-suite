### 5.2 Sequence for a tasker case

1. `calAuth` (worker) and `receiverHandle` (worker) are in place.
2. `P2-CAL-WH-*`: `client.webhooks.create({subscriberUrl: receiverHandle.urlFor(testId), eventTriggers, secret})`.
3. API v2 booking (`lane booking helper`), which queues one Task per webhook.
4. Set receiver mode (`receiver.setMode`).
5. `runTaskerOnce` (GET cron, bearer). It returns after the tasks settle.
6. Oracle: deliveries (`receiver.deliveries`) and Task rows (`taskRowsFor`).
7. Cleanup in `finally`: cancel bookings, remove webhook, revoke key (section 7).

### 5.3 Sequence for a scheduled case

1. Webhook with `MEETING_STARTED`; booking (scheduled row created with `startAfter` = startTime).
2. Row located by `bookingUid` (`qa_ro`).
3. `createFixtureWriter` update of `startAfter` to a past instant (`caseId` = the case, allow-listed).
4. `fireScheduledTriggersOnce` (POST cron, raw key). Deliveries are not awaited by the product: `expect.poll(() => receiver.deliveries(key).length, { timeout: SLO.calWebhookDelivery.ms, intervals: POLL_INTERVALS })`.
5. Oracle: deliveries and the row (`qa_ro`, `expect.poll` on row count, same budget).

### 5.4 `test.fail` pattern (all three finding classes)

Each finding is two tests in one file: a positive control (passes, asserts the setup and the expected product value up to the finding) and a
`test.fail` test that repeats the setup and places `test.fail()` immediately before the single product assertion. Reason: Playwright's
`test.fail` passes when any assertion in the test fails, so a broken setup inside the same test would pass as an expected failure. Playwright
1.64.0 behaviour for this is not probed (UNPROBED); the builder checks it once in L2 by a deliberately broken setup in a throwaway spec (not
committed) and reports the result.

```ts
import type { CalAuth } from "../../auth/cal.ts";
import type { ApiRequestLike } from "../../clients/base.ts";

export const SLOTS_VERSION = "2024-09-04";
export const BOOKINGS_VERSION = "2024-08-13";

export interface BookingRequest {
  readonly eventTypeId: number;
  /** An ISO instant returned by slots() (never invented). */
  readonly start: string;
  readonly attendeeEmail: string;
  readonly attendeeName: string;
}

export interface BookingResult {
  readonly status: number;
  /** Recurring event types answer an array of occurrences (P7). */
  readonly uids: readonly string[];
  readonly recurringSeriesLength: number;
  readonly bodyHead: string;
}

/** Headers for API v2. The key is revealed only into the request, never logged. */
export function apiHeaders(auth: CalAuth, version: string): Record<string, string> {
  return { "cal-api-version": version, authorization: auth.headerValue.reveal(), "content-type": "application/json" };
}

export function calBookingApi(input: { request: ApiRequestLike; apiBaseUrl: string; auth: CalAuth }) {
  const { request, apiBaseUrl, auth } = input;
  return {
    async slots(q: { eventTypeId: number; fromIsoDate: string; toIsoDate: string; timeZone: string }): Promise<string[]> {
      const url = `${apiBaseUrl}/v2/slots?eventTypeId=${q.eventTypeId}&start=${q.fromIsoDate}&end=${q.toIsoDate}&timeZone=${encodeURIComponent(q.timeZone)}`;
      const res = await request.fetch(url, { headers: apiHeaders(auth, SLOTS_VERSION), failOnStatusCode: false, timeout: 30_000 });
      const body = JSON.parse(await res.text()) as { data?: Record<string, { start: string }[]> };
      return Object.values(body.data ?? {}).flat().map((s) => s.start);
    },
    async create(req: BookingRequest): Promise<BookingResult> {
      const res = await request.fetch(`${apiBaseUrl}/v2/bookings`, {
        method: "POST",
        headers: apiHeaders(auth, BOOKINGS_VERSION),
        data: JSON.stringify({ start: req.start, eventTypeId: req.eventTypeId, attendee: { name: req.attendeeName, email: req.attendeeEmail, timeZone: "Europe/London" } }),
        failOnStatusCode: false,
        timeout: 30_000,
      });
      const text = await res.text();
      const body = JSON.parse(text || "{}") as { data?: unknown };
      const list = Array.isArray(body.data) ? (body.data as { uid?: string }[]) : body.data ? [body.data as { uid?: string }] : [];
      return { status: res.status(), uids: list.map((x) => x.uid ?? "").filter((u) => u !== ""), recurringSeriesLength: Array.isArray(body.data) ? list.length : 0, bodyHead: text.slice(0, 80) };
    },
    async cancel(uid: string, reason: string): Promise<number> {
      const res = await request.fetch(`${apiBaseUrl}/v2/bookings/${uid}/cancel`, {
        method: "POST",
        headers: apiHeaders(auth, BOOKINGS_VERSION),
        data: JSON.stringify({ cancellationReason: reason }),
        failOnStatusCode: false,
        timeout: 30_000,
      });
      return res.status();
    },
  };
}
```

`timeZone` on the attendee is a fixed `Europe/London` for the lane's standard bookings (the attendee's zone does not change the slot list).

```ts
/** Flips the low bit of one byte. The only tamper used by the lane (negative control). */
export function tamperOneByte(raw: Buffer, index = 0): Buffer {
  if (index < 0 || index >= raw.length) throw new Error(`TEST BUG: tamper index ${String(index)} outside ${String(raw.length)} bytes`);

}
```

### 6.6 `src/lanes/cal/oas-walk.ts`

```ts
export interface GetOperation {
  readonly method: "get";
  readonly path: string;
  readonly params: readonly string[];
}

/** Every GET operation of an OpenAPI 3.0 document (plain object, not dereferenced). Pure. */
export function listGetOperations(doc: { paths?: Record<string, Record<string, unknown>> }): GetOperation[] {
  const out: GetOperation[] = [];
  for (const [path, item] of Object.entries(doc.paths ?? {})) {
    if (!("get" in item)) continue;
    const params = [...path.matchAll(/\{([^}]+)\}/g)].map((m) => m[1] ?? "");
    out.push({ method: "get", path, params });
  }
  return out;
}

/** Substitutes `{name}` with a value; throws when a parameter has no value (the crawler then lists it as UNCRAWLED). */
export function fillPath(path: string, values: Readonly<Record<string, string>>): string {
  return path.replace(/\{([^}]+)\}/g, (_, name: string) => {
    const v = values[name];
    if (v === undefined) throw new Error(`TEST BUG: no value for path parameter ${name} in ${path}`);
    return encodeURIComponent(v);
  });
}
```

## 7. Data isolation, cleanup and leak check

- Run prefix: `currentRunPrefix()` (`src/run/prefix.ts`), set once by `playwright.config.ts`. Every entity the lane creates carries it:
  - webhook subscriber URL: `/r/<prefix>/<testId>` (receiver), which the leak rule `cal-leak-webhook-url` checks;
  - API key note: `calAuth` label, checked by `cal-leak-api-key-note`;
  - attendee emails: `<prefix>-<label>@example.com`;
  - scheduled rows: `subscriberUrl` carries the prefix (new rule `cal-leak-scheduled-trigger`);
  - Task rows: `payload` carries the subscriber URL (no leak rule, D17).
- Creates and removal:

| Entity | Created by | Removed by | Leak rule |
|---|---|---|---|
| Webhook | `webhook/create` (`src/clients/cal.ts`) | `webhook/delete` (`client.webhooks.remove`) | `cal-leak-webhook-url` |
| Scheduled rows | booking or webhook create | cascade with the webhook and the booking; fired rows deleted by the cron | new `cal-leak-scheduled-trigger` |
| Booking (ACCEPTED or PENDING) | API v2 `POST /v2/bookings` | API v2 `POST /v2/bookings/{uid}/cancel` (cancelled rows stay, status CANCELLED) | new `cal-leak-booking-active` |
| API key | `calAuth` (worker) and the CON-005/FC-3 keys | `auth.revoke()` | `cal-leak-api-key-note` |
| Task rows | the tasker, from bookings | none (D17) | none (accepted) |
| Event type (PENDING case, L3 step 0 only) | API v2 `POST /v2/event-types` (UNPROBED) | `DELETE /v2/event-types/{id}` (UNPROBED) | `cal-leak-event-type-slug` (after cleanup) |

- Shared seed state: the lane writes none. It does not change the pro user's availability, timezone or event types. If an L3 probe needs a seed change, it is restored in `finally` and asserted, or the case is deferred (D18).
- Counts: tests read counts only for their own run prefix, except the "zero writes" checks (DLY-003, SCH-003 deliveries, FC-3). Those are global, valid because `workers` is 1 (`src/invariants/fixture.ts` asserts it), and the run is serialised by the project order.
- Cleanup order in `finally`: cancel bookings (each uid), remove webhooks, `receiver.setMode(ok)`, then `auth.revoke()`. The P2-X-DB-001 sweep runs after the test body, so it sees the cleaned state.

## 15. Autonomous build protocol (the build runs later, in separate sessions, one task per session)

1. Start from `origin/main` (or the previous task branch, section 1). Create the task branch. Follow sections 8 and 9.
2. Commit with explicit paths (section 11). Push with `git push -u origin <branch>` (no force). Retry a failed push up to four times with backoff only for network errors.
3. Open the PR with the GitHub MCP tool `mcp__github__create_pull_request`. The repository has no pull request template file at `.github/`, so the body is: summary, counts (section 9 items 2 to 4), open decisions it depends on, and the probe file references. No session link, no co-author line (section 16).
4. Subscribe the session to the PR with `subscribe_pr_activity` (CI events). Fix CI failures by root cause (file:line), label PRODUCT BUG, TEST BUG or ENV with evidence, and push again. Never skip, disable or quarantine a test to get green. Never change a `test.fail` expectation to make it pass.
5. The builder never merges, tags, dispatches a workflow, or requests an AI review. The owner does those.
6. The task report (section 17 format) is the last chat message of the session.

## 16. Repo rules applied (plan and build)

1. No personal names in repo text; roles only (the owner, the maintainer, the builder). The planning session writes no name.
2. No Co-authored-by lines, no "Generated with" lines, no session links in commits or PR text. The session-link attribution in the session's reminder is NOT applied to repo text, because the repo rule (this plan, rule 2) takes precedence; the trailer gate in section 9 checks for it.
3. No edit to product forks, their `.env` files, `node_modules`, or the harness.
4. No secret printed; test secrets are per run and passed through the environment only.
5. No weakened assertion, raised timeout, retry, sleep, or skip to get green.
6. Every failure root-caused with file:line; labels PRODUCT BUG, TEST BUG, ENV, NOT A BUG.
7. Named by ID only: none of the three reserved IDs is used in this plan.
8. Lowercase Conventional Commits, explicit paths, no `git add -A` or `git add .`.
