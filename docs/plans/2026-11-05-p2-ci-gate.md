## 4. Design

### 4.1 Pattern: why caller/callee

- P1 (`p1-e2e.yml` calls `e2e.yml` with `secrets: inherit`) is the house pattern. A top-level caller
  gives one Actions run per PR or push, and one required check.
- P6 (`perf.yml`) is one fat workflow. P2 keeps one file per lane, because each lane owns its file
  (`docs/lane-ownership.md:12-17`). A fat file would make lanes edit one shared file, which the
  ownership rules forbid. Reusable calls keep the ownership.
- The gate is one job with `if: ${{ always() }}`, so a failed or cancelled dependency fails the gate
  instead of being silently skipped.

### 4.2 Job graph

```
ci (on: pull_request, push: main, workflow_dispatch)
  changes ----------------------+--------------------+-----------------+
  api  (uses api.yml)           |                    |                 |
  env-check (uses env-check.yml)|                    |                 |
  p2-cal (needs changes; uses p2-cal.yml; secrets: inherit)            |
  p2-doc (needs changes; uses p2-doc.yml; secrets: inherit)            |
  p2-med (needs changes; uses p2-med.yml; secrets: inherit)            |
  p2-tw  (needs changes; uses p2-tw.yml)                               |
  gate (needs changes, api, env-check, p2-cal, p2-doc, p2-med, p2-tw; if: always())
```

Each callee keeps its own jobs. In the UI a called job shows as `<caller job> / <callee job>`, for
example `api / check`, `api / foundation`, `p2-cal / cal-api`. The gate reads only the caller job
result. A caller job that calls a reusable workflow has the result of that workflow.

### 4.3 The path classifier

`changes` runs `scripts/ci-changes.sh` (section 5.8). It emits four flags. A flag is `true` when the
lane must run.

| Event | Flags |
|---|---|
| `workflow_dispatch` | all `true` (manual run of everything) |
| `push` (main) | all `false` (lanes never ran on push; the cost profile stays the same) |
| `pull_request`, empty changed list | all `true` (fail-safe: no list means no evidence) |
| `pull_request`, changed list | per path rules below |

Path rules, applied to each changed path in order. The first matching rule wins for that path.
Any path that matches no rule sets all four flags (fail-safe default).

| Rule | Regex (anchored, ERE, used with bash `=~`) | Effect |
|---|---|---|
| cal | `^(src/lanes/cal/\|tests/unit/lanes/cal/\|tests/contracts/cal/\|tests/integration/cal/\|tests/webhooks/cal/\|tests/serial/cal/\|tests/fixtures/cal/\|contracts/cal/\|src/invariants/lanes/cal\.ts$\|\.github/workflows/p2-cal\.yml$)` | cal `true` |
| med | `^(src/lanes/med/\|tests/unit/lanes/med/\|tests/contracts/med/\|tests/integration/med/\|tests/webhooks/med/\|tests/serial/med/\|contracts/med/\|src/invariants/lanes/medusa\.ts$\|src/slo/medusa\.ts$\|\.github/workflows/p2-med\.yml$)` | med `true` |
| doc | `^(src/lanes/doc/\|tests/unit/lanes/doc/\|tests/contracts/doc/\|tests/integration/doc/\|tests/webhooks/doc/\|tests/serial/doc/\|tests/billing/doc/\|tests/fixtures/doc/\|contracts/doc/\|src/invariants/lanes/documenso\.ts$\|src/slo/documenso\.ts$\|\.github/workflows/p2-doc\.yml$)` | doc `true` |
| tw | `^(src/lanes/tw/\|tests/unit/lanes/tw/\|tests/contracts/tw/\|tests/integration/tw/\|tests/webhooks/tw/\|tests/serial/tw/\|src/clients/twenty\.ts$\|\.github/workflows/p2-tw\.yml$\|\.github/workflows/tw-study\.yml$)` | tw `true` |
| neutral | `^(docs/\|README\.md$)` | nothing (lanes unaffected; api and env-check still run) |
| anything else | (no rule matched) | all four `true` |

Why these paths: the lane rows in `docs/lane-ownership.md:14-17` and the lane-owned shared-index
entries (`src/invariants/lanes/cal.ts`, `medusa.ts`, `documenso.ts`, `src/slo/medusa.ts`,
`src/slo/documenso.ts`). `src/clients/twenty.ts` is the one shared file the tw lane changed
(`docs/lane-ownership.md:61`). Everything else that a lane test can read (`src/db/`, `src/contracts/`,
`src/invariants/rules.ts`, `tests/db/`, `scripts/`, `package*.json`, `playwright.config.ts`,
`.github/workflows/api.yml`, `ci.yml`, `tests/unit/ci/`) is "anything else", so it runs all lanes.
That is the safe direction.

### 4.4 Fork and secret rules (defence in depth, documented on both files)

- Caller (`ci.yml`): each lane job has `if:` that requires the flag **and** the same-repo test (or a
  manual run). A fork PR never calls a lane. The flag is set from paths only, so a fork PR that
  touches a lane is red at the gate (D1).
- Callee (`p2-*.yml`): each job keeps the same-repo guard, and gains a `workflow_call` clause. The
  clause only stops a called job from being skipped by its own guard when the event name reads as
  `workflow_call` (open item U2). It is safe because the caller job is the real guard: a fork never
  reaches the callee.
- `secrets: inherit` only where the callee references a secret. For `ci.yml` this is `p2-cal`,
  `p2-doc`, `p2-med`. `p2-tw` references no secret, so it gets no `secrets:` key. The unit test
  checks this match (section 6, E-group).
- No secret value appears in any YAML written here. Only the names, and only in the callees.

### 4.5 Gate rules (the one required check)

The gate passes only when all of these hold. Anything else is red.

1. `changes` result is `success`. (A failed `changes` skips every lane, so it must be checked directly.)
2. `api` result is `success`. (`api` includes `foundation`, which already demands all four api jobs.)
3. `env-check` result is `success`.
4. For each lane `L` in `p2-cal`, `p2-doc`, `p2-med`, `p2-tw`:
   - if its flag is `true`: the result must be `success`. `skipped`, `failure`, `cancelled`, or a
     missing job are all red.
   - if its flag is `false`: `success` or `skipped` are green. `failure`, `cancelled` or a missing job
     are red.
5. A flag that is not exactly `true` or `false` (for example, empty) is red.

`skipped` counts as a pass only when its flag is `false`. That is the single rule that keeps
"docs-only" green without letting a broken `if:` slip through.

### 5.1 `.github/workflows/ci.yml` (new, full file)

```yaml
# Single PR and push gate for P2 (docs/plans/2026-11-05-p2-ci-gate.md).
# Each lane owns its own workflow file, which declares workflow_call (and workflow_dispatch so one lane
# can still be run by hand). This file calls them, so one Actions run lists every job, and `gate` is the
# one check the Main ruleset requires. Scheduled work stays in tw-study.yml and is never called here.
# Forks: a fork PR never calls a lane (the lane flag and the caller `if:` both require the same repo).
# A fork PR that changes a lane path is red at the gate by design (docs/lane-ownership.md, "Gate").
name: ci

on:
  pull_request:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  changes:
    name: changes
    runs-on: ubuntu-24.04
    # CHANGES_TIMEOUT basis: one checkout with full history and one git diff. 5 min is the checkout
    # budget the lanes use (p2-cal.yml:35).
    timeout-minutes: 5
    outputs:
      p2_cal: ${{ steps.decide.outputs.p2_cal }}
      p2_doc: ${{ steps.decide.outputs.p2_doc }}
      p2_med: ${{ steps.decide.outputs.p2_med }}
      p2_tw: ${{ steps.decide.outputs.p2_tw }}
    steps:
      - name: Checkout (full history, so the merge base exists)
        timeout-minutes: 5
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          fetch-depth: 0
          persist-credentials: false
      - name: Changed paths (pull_request only; an empty list otherwise)
        timeout-minutes: 2
        env:
          EVENT_NAME: ${{ github.event_name }}
          BASE_SHA: ${{ github.event.pull_request.base.sha }}
          HEAD_SHA: ${{ github.event.pull_request.head.sha }}
        run: |
          set -euo pipefail
          if [ "$EVENT_NAME" = "pull_request" ]; then
            git diff --name-only "$BASE_SHA...$HEAD_SHA" > "$RUNNER_TEMP/changed.txt"
          else
            : > "$RUNNER_TEMP/changed.txt"
          fi
      - name: Decide which lanes run (rules in scripts/ci-changes.sh)
        id: decide
        timeout-minutes: 2
        env:
          EVENT_NAME: ${{ github.event_name }}
        run: bash scripts/ci-changes.sh < "$RUNNER_TEMP/changed.txt"

  # No timeout-minutes on the caller jobs below: each callee job sets its own (api 10, lanes 30 to 120).
  api:
    name: api
    uses: ./.github/workflows/api.yml

  env-check:
    name: env-check
    uses: ./.github/workflows/env-check.yml

  p2-cal:
    name: p2-cal
    needs: [changes]
    if: ${{ needs.changes.outputs.p2_cal == 'true' && (github.event_name == 'workflow_dispatch' || github.event.pull_request.head.repo.full_name == github.repository) }}
    uses: ./.github/workflows/p2-cal.yml
    secrets: inherit

  p2-doc:
    name: p2-doc
    needs: [changes]
    if: ${{ needs.changes.outputs.p2_doc == 'true' && (github.event_name == 'workflow_dispatch' || github.event.pull_request.head.repo.full_name == github.repository) }}
    uses: ./.github/workflows/p2-doc.yml
    secrets: inherit

  p2-med:
    name: p2-med
    needs: [changes]
    if: ${{ needs.changes.outputs.p2_med == 'true' && (github.event_name == 'workflow_dispatch' || github.event.pull_request.head.repo.full_name == github.repository) }}
    uses: ./.github/workflows/p2-med.yml
    secrets: inherit

  p2-tw:
    name: p2-tw
    needs: [changes]
    if: ${{ needs.changes.outputs.p2_tw == 'true' && (github.event_name == 'workflow_dispatch' || github.event.pull_request.head.repo.full_name == github.repository) }}
    uses: ./.github/workflows/p2-tw.yml

  gate:
    name: gate
    needs: [changes, api, env-check, p2-cal, p2-doc, p2-med, p2-tw]
    if: ${{ always() }}
    runs-on: ubuntu-24.04
    # GATE_TIMEOUT basis: jq and bash only, no install, no network. 5 min is the foundation precedent in
    # api.yml (`timeout-minutes: 5` on the foundation job).
    timeout-minutes: 5
    env:
      NEEDS: ${{ toJSON(needs) }}
      P2_CAL: ${{ needs.changes.outputs.p2_cal }}
      P2_DOC: ${{ needs.changes.outputs.p2_doc }}
      P2_MED: ${{ needs.changes.outputs.p2_med }}
      P2_TW: ${{ needs.changes.outputs.p2_tw }}
    steps:
      - name: Every required job passed (skipped counts as a pass only when its lane flag is false)
        timeout-minutes: 2
        run: |
          set -euo pipefail
          echo "$NEEDS" | jq -r 'to_entries[] | "\(.key): \(.value.result)"'
          fail=0
          # result <job>: the job's result, or "missing" when the job is not in needs.
          result() { echo "$NEEDS" | jq -r --arg job "$1" '.[$job].result // "missing"'; }
          # must <job> <flag>: flag is true or false. changes, api and env-check always pass "true".
          must() {
            local job="$1" flag="$2" r
            r="$(result "$job")"
            case "$flag" in
              true|false) ;;
              *) echo "::error::$job: lane flag is '$flag', expected true or false"; fail=1; return 0 ;;
            esac
            case "$r" in
              success) ;;
              skipped)
                if [ "$flag" = "true" ]; then
                  echo "::error::$job was skipped but its lane flag is true. A fork PR that changes this lane lands here by design: reopen the change from a branch in this repository."
                  fail=1
                fi
                ;;
              *) echo "::error::$job finished with result '$r'"; fail=1 ;;
            esac
            return 0
          }
          must changes true
          must api true
          must env-check true
          must p2-cal "$P2_CAL"
          must p2-doc "$P2_DOC"
          must p2-med "$P2_MED"
          must p2-tw "$P2_TW"
          exit "$fail"
```

  exact `run: |` at 8 spaces and the body at 10 spaces, the same layout `stepScript` expects.
- `changes` writes its outputs through `$GITHUB_OUTPUT` from the script (5.8). Do not write them in YAML.

### 5.8 `scripts/ci-changes.sh` (new)

```bash
#!/usr/bin/env bash
# Decides which P2 lane jobs ci.yml runs (docs/plans/2026-11-05-p2-ci-gate.md, section 4.3).
# Stdin: changed paths, one per line (empty unless the event is a pull request).
# Env: EVENT_NAME (github.event_name). Output: p2_cal, p2_doc, p2_med, p2_tw as true or false,
# written to $GITHUB_OUTPUT, or to stdout when GITHUB_OUTPUT is unset (unit tests use that).
# Fail-safe: a path no rule matches runs every lane. An empty list on a pull request runs every lane.
set -euo pipefail

re_cal='^(src/lanes/cal/|tests/unit/lanes/cal/|tests/contracts/cal/|tests/integration/cal/|tests/webhooks/cal/|tests/serial/cal/|tests/fixtures/cal/|contracts/cal/|src/invariants/lanes/cal\.ts$|\.github/workflows/p2-cal\.yml$)'
re_med='^(src/lanes/med/|tests/unit/lanes/med/|tests/contracts/med/|tests/integration/med/|tests/webhooks/med/|tests/serial/med/|contracts/med/|src/invariants/lanes/medusa\.ts$|src/slo/medusa\.ts$|\.github/workflows/p2-med\.yml$)'
re_doc='^(src/lanes/doc/|tests/unit/lanes/doc/|tests/contracts/doc/|tests/integration/doc/|tests/webhooks/doc/|tests/serial/doc/|tests/billing/doc/|tests/fixtures/doc/|contracts/doc/|src/invariants/lanes/documenso\.ts$|src/slo/documenso\.ts$|\.github/workflows/p2-doc\.yml$)'
re_tw='^(src/lanes/tw/|tests/unit/lanes/tw/|tests/contracts/tw/|tests/integration/tw/|tests/webhooks/tw/|tests/serial/tw/|src/clients/twenty\.ts$|\.github/workflows/p2-tw\.yml$|\.github/workflows/tw-study\.yml$)'
re_neutral='^(docs/|README\.md$)'

cal=false; med=false; doc=false; tw=false; all=false
case "${EVENT_NAME:-}" in
  workflow_dispatch)
    all=true
    ;;
  pull_request)
    count=0
    while IFS= read -r path; do
      [ -z "$path" ] && continue
      count=$((count + 1))
      if [[ $path =~ $re_cal ]]; then cal=true
      elif [[ $path =~ $re_med ]]; then med=true
      elif [[ $path =~ $re_doc ]]; then doc=true
      elif [[ $path =~ $re_tw ]]; then tw=true
      elif [[ $path =~ $re_neutral ]]; then :
      else all=true
      fi
    done
    if [ "$count" -eq 0 ]; then all=true; fi
    ;;
  *)
    # push and any other event: no lanes. api and env-check still run in ci.yml.
    ;;
esac

if [ "$all" = true ]; then cal=true; med=true; doc=true; tw=true; fi
out="${GITHUB_OUTPUT:-/dev/stdout}"
printf 'p2_cal=%s\np2_doc=%s\np2_med=%s\np2_tw=%s\n' "$cal" "$doc" "$med" "$tw" >> "$out"
```

Notes:

- Regex text must stay identical to section 4.3. The unit tests (section 6, G-group) pin the behaviour.
- `[[ ... =~ $var ]]` takes the regex from the variable unquoted. Do not quote it.
- Leave the file mode as the checkout gives it. The workflow calls it with `bash`, so no exec bit is needed.

## 11. Owner hand steps (ruleset, verbatim)

Do this after the build PR is green and before merge. This avoids two dead ends: `gate` required but not
yet on the PR, or the old checks removed while nothing replaces them.

1. Open the green PR and confirm the check named `gate` is present and success.
2. GitHub → repo Settings → Rules → ruleset `protect-main` → Require status checks to pass.
3. Remove required checks: `env-check`, `check`, `unit`, `db-guard`.
4. Add required check: `gate` (the exact job name from `ci.yml`; if the UI shows `ci / gate`, use that
   string. Record which string the PR check list actually shows, as in E2).
5. Save the ruleset.
6. Confirm the PR's merge box now waits only on `gate`.
7. Merge with a merge commit (never squash), then run the cleanup in section 12.

Why the old names disappear: after this change `api.yml` and `env-check.yml` run as called jobs, so their
checks are reported as `api / check`, `api / unit`, `api / db-guard`, `env-check / env-check`. The old names
are not reported any more. Until step 3 is done, the PR would wait for checks that never arrive. That is
the reason the order is: green run, swap, merge.

Sessions never change the ruleset, never merge, never tag, never dispatch.
